LLM Endpoints (2)
POST /api/chat
Full LLM pipeline — non-deterministic, ~1–10s latency

Step 1 — Intent detection (pure Python, no LLM)
Regex-based: add, remove, update qty, clear, bundle, bundle-confirm, compare, reorder, top-rated

Step 2 — RAG retrieval (embed model)
Query → nomic-embed-text-v2-moe → ChromaDB → top-k product docs
Fallback: spec SQL search (crud.search_products_by_spec)

Step 3 — Prompt assembly
System prompt + conversation history + retrieved product context assembled in memory

Step 4 — Ollama LLM call (gemma4:e2b)
ChatOllama.invoke() → generates natural-language reply

Returns: response (str), cart_updated (bool), products_mentioned (list)
POST /api/chat/stream
Same pipeline as /api/chat — but streamed via SSE

Returns text/event-stream — one data: line per event:
  • {"type":"token","content":"…"} — partial text
  • {"type":"done","cart_updated":…,"bundle_items":…,"pending_options":…}
  • {"type":"error","content":"…"}

LLM is invoked via ChatOllama.astream() — async token-by-token
Latency to first token: ~200–800ms. Total: same as /api/chat
⚠ Testing implications
• Results are non-deterministic — same input may yield different wording each run
• Response time varies widely (model load, context size)
• Requires Ollama running with gemma4:e2b loaded
• Use GEval / deepeval for quality assertions, not exact string matching
• Side-effects: may modify cart, _pending_add, _pending_bundle in memory
